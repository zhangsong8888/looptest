## 0. 结论摘要

### 0.1 一句话结论

本设计把「低空起降调度系统」收敛为**起降场侧的资源编排与协同工具**：以「资源—预约—占用」三条时间轴为骨架，以**可解释的规则判定**替代口头协调，以**主状态 + 子状态 + 阻塞原因**表达复杂现场，以**全量审计**保证每一次改槽、让行、取消都能回溯。系统输出建议与状态，不替代管制指令。

## 1. 需求规格（设计口径）

### 1.1 背景、范围与目标

低空运行在起降场这一层的痛点不是「没有系统」，而是「系统里的台账不能参与判定」：停机位占用靠对讲机、计划与实况脱节、场地状态各叫各的名字（行业痛点见 E-12；实时占用模型见 E-15）。上游已把问题、角色、范围讲清（requirement.md 1.1～1.5），本设计只回答一个问题：**怎样把这些台账变成研发能实现、调度员敢用、验收能复现的判定与交互。**

| 目标 | 设计含义 | 可观察结果 |
| --- | --- | --- |
| G1 资源可视 | 场—单元—机位—设备四类资源统一台账，状态带时间戳与来源 | P-01 每张场卡片能看到「当前是否可收、可放、可停」 |
| G2 冲突可判 | 重叠、缓冲、周转、容量四类冲突在提交时判定，不靠人盯（时间冲突定义见 E-22） | 冲突用例 20/20 拦截，正常用例误判 ≤2% |
| G3 变更可解释 | 每次拒绝/改槽返回「哪条规则、哪个资源、哪个时间窗、哪个参数」（方案审批见 E-21；变更留痕见 E-18） | 冲突提示能显示「与 XX 架次在 U1 10:05–10:10 重叠，缓冲 60s」 |
| G4 过程可追溯 | 人工写操作原因必填；系统动作有来源标记；审计不可改 | 抽查任意改槽，能还原前后值与操作人 |
| G5 边界可合规 | UI 与对外文档固定声明「建议不构成管制指令」；容量只读评估值 | 对外材料不出现「本系统放行/管制」表述 |
| G6 演示可复现 | 固定业务日、固定数据集、固定异常脚本、可倍速回放 | AC-18 一键回放，指标可复算 |

### 1.2 角色与权限矩阵

**目标用户**按三个角色族：①起降场运营方（调度员、起降场运营管理员）——首版主用户，负责资源编排与现场处置；②运营人（企业管理员、飞行操作员）——提交架次、确认改槽、报起飞/落地；③监管与平台方（监管只读、系统管理员）——只读态势/审计与参数治理。首版优先服务前两类，监管只读用于验收与合规演示。

> 角色族沿用上游 1.2；「调度员 / 运营管理员 / 运营人 / 飞行操作员 / 监管 / 系统管理员」六类。首版不实现完整六席位（E-13 的席位是低空飞行服务系统的人机界面要求，不是本系统的组织编制），只落「运行协调席 + 运营人 + 监管只读」三角色族，其余为扩展位。

**四条权限硬约束（研发不要「优化」掉）**

1. **数据范围先于功能权限**：运营人只能看到本企业架次的成本/客户字段；调度员不能看到运营人合同价；监管只读不得导出含个人信息的明细。
2. **双人复核（four-eyes）** 只用于四类高风险动作：强制释放他人已确认预约、跨优先级人工调序、强制让行改槽（普通让行只需被让行方确认）、场地状态「失联后强制覆盖」。两名不同账号，均写审计。
3. **系统管理员不能改业务数据**：只能改参数、账号、接口配置；参数变更需二次确认，并生成新版本与生效时间。
4. **移动端不继承后台全量权限**：飞行操作员只可见本人执飞架次，且只做「查槽 / 确认改槽 / 报起飞 / 报落地」四件事。

### 1.3 业务流程设计

#### 1.3.1 主流程（Happy Path）

```
运营人创建架次
  → 准入校验（R-17 状态新鲜度，R-01 场地/时段，R-02 机型/设施）
  → 排槽（R-03 粒度，R-04 互斥，R-05 缓冲，R-06 周转，R-07 容量，R-16 双段）
  → 锁定槽（TTL）→ 运营人/调度员确认 → 已确认
  → T-15min 起飞前确认（R-11）→ 待起飞
  → 报起飞 → 离场（占起降单元）→ 在途
  → 报进近 → 进近 → 报落地 → 已落地（垂直起降即释放；跑道型按 exitSeconds）
  → 分配停机位（R-12）→ 保障中（周转计时）
  → 报离场 → 完成（释放机位）→ 统计/审计
```

**贯穿约束**：除纯校验类拒绝外，任何「系统自动」动作都必须可被人工否决；否决动作写审计（R-14）。

#### 1.3.2 F-01 创建与排槽

| 步 | 动作 | 系统行为 | 失败分支 |
| --- | --- | --- | --- |
| 1 | 运营人填架次：起降场、机型、计划时刻、任务类型、优先级、是否充换电 | 校验必填与时间格式；缺时区/秒精度返回 `INVALID_TIME` | 表单原地提示，不落库 |
| 2 | 提交 | 生成 `version=1`，状态「待排槽」；执行 R-17/R-01/R-02（`approvalGateMode=slot` 时先校验审批态） | `SITE_CLOSED` / `SITE_FAULT` / `SITE_RESTRICTED` / `OUT_OF_WINDOW` / `AIRCRAFT_NOT_SUPPORTED` |
| 3 | 排槽 | 时刻向下对齐槽粒度（R-03）；查同资源区间（R-04/R-05）；查机位周转可行性（R-06）；查小时容量（R-07）；`slot` 模式下审批态未通过则拒绝 | `SLOT_CONFLICT` / `BUFFER_VIOLATION` / `TURNAROUND_VIOLATION` / `CAPACITY_EXCEEDED` |
| 4 | 双段槽 | 起飞槽与落地槽分别锁槽（R-16）；跨场时两场同锁，同场时两段同锁 | 任一失败 → 回滚另一段，返回失败场/段与原因 |
| 5 | 锁定 | 生成两段「锁定」预约，TTL 10 min（建议值）；返回两段的精确计划时刻与对齐槽 | TTL 到期未确认 → `已过期`，槽回「可用」 |
| 6 | 确认 | 运营人或调度员一次确认两段；写 `confirmedBy/confirmedAt`；状态「已确认」 | 任一段被抢占 → 整单 `SLOT_CONFLICT`，提示改槽或排队 |
| 7 | 无槽 | 返回最近可用窗口 + 建议改场/改时；运营人选择排队 | 入队（R-08），状态「排队中」 |

#### 1.3.3 F-02 起飞前确认与放行

| 步 | 触发 | 系统校验 | 结果 |
| --- | --- | --- | --- |
| 1 | `T - preflightConfirmMinutes`（建议 15 min） | 场地/单元状态可用；无未解除管制/气象禁飞；机位可用；前序未造成单元冲突；飞行计划审批态为审批通过或书面豁免（`approvalGateMode=release`） | 全通过 → 「待起飞」，记录放行人 |
| 2 | 同上 | 任一不通过 | 状态仍为「已确认」，`subStatus=暂缓放行`，`blockingReasons` 列出阻塞项；**不得自动放行** |
| 3 | 运营人未在窗口内确认 | 系统只提醒，不代确认 | 超窗 → 「延误」；是否释放槽按 R-10 判定，**不自动放行** |
| 4 | 调度员处置阻塞项 | 解除后重新校验 | 通过 → 「待起飞」；仍不通过 → 保持暂缓，写原因 |
| 5 | 放行后场地突变 | 订阅 R-13 事件 | 撤回放行，回「已确认/暂缓」，通知运营人 |

**文案硬约束**：放行按钮附近固定显示「本系统放行仅代表起降场资源就绪，不代表空管许可/飞行活动批准」。

#### 1.3.4 F-03 落地、机位分配与周转

| 步 | 动作 | 系统行为 | 异常 |
| --- | --- | --- | --- |
| 1 | 报落地（人工/监视数据补录） | 记录 `actualLandingAt`、来源；垂直起降单元接地即释放，跑道型按 `runwayExitSeconds` 释放 | 无落地报 → 按监视数据补录并标 `source=interface`；无监视 → 保持「进近」并告警 |
| 2 | 分配机位 | 按「机型适配 → 充换电需求 → 就近 → 周转可行」排序；写占用区间 | 无机位 → `subStatus=等待机位`，状态「已落地」，容量告警；**不得默认占任一机位** |
| 3 | 等待重试 | 每 `standRetryMinutes`（建议 1 min）重试；可人工指定机位（需原因） | 超 `standWaitTimeout`（建议 30 min）→ 升级告警，建议拖车/改场 |
| 4 | 周转计时 | `standFreeAt = actualLandingAt + turnaround + chargingMinutes` | 超周转时长 → 告警，不自动释放 |
| 5 | 报离场 | 释放机位；状态「完成」；写周转时长 | 未报离场 → 按计划离场 + 容差提醒；超时升级 |

#### 1.3.5 F-04 延误、改槽与让行

| 场景 | 触发 | 系统行为 | 人工确认 |
| --- | --- | --- | --- |
| 延误重排 | 预测/实际起飞晚于 `slotEnd + tolerance`（建议 2 min） | 释放原槽，状态「延误」，按 R-08 重排，推送 2～3 个改槽建议 | 运营人确认后生效；不确认则保留排队 |
| 主动改槽 | 运营人/调度员发起 | 先算影响面：受影响后续架次、机位占用、跨场联动；弹层确认后落库 | 必须填原因；跨优先级需双人复核 |
| 让行 | 高优先级无槽，存在低优先级「已确认」槽 | 生成让行建议（Directive），通知双方与调度员 | 默认被让行方确认；强制让行默认关闭（开启需双人复核 + 规则依据）；**不自动改槽** |
| 拒绝让行 | 被让行方拒绝 | 原预约不变；记录「未获让行」；高优先级继续排队 | 默认不得强改；调度员可改其他资源 |
| 建议过期 | 超过 `directiveTtl`（建议 10 min） | 置「已过期」，置灰，提示重新计算 | 重新生成，不复用旧建议 |

#### 1.3.6 F-05 场地状态突变（停航/故障/管制）

| 步 | 系统行为 | 约束 |
| --- | --- | --- |
| 1 | 更新场地状态 + 子状态 + 原因 + 预计恢复时间；写状态快照 | 状态变更必须带来源（人工/接口）与生效时间 |
| 2 | 禁止新增预约；已有「锁定」预约置「已作废」 | 锁定预约释放要通知运营人 |
| 3 | 未来 `affectedWindowMinutes`（建议 120 min）内「已确认」预约 → `subStatus=待重排`，生成改槽/改场建议；已进入起飞前确认窗口/已放行的按 R-11 暂缓或撤回 | 不自动取消，不自动改场 |
| 4 | 「在途/进近」架次 → 推送备降建议 | **不自动改航**；备降场选择由运营人/机组决定 |
| 5 | 状态恢复「开航」 | 解除限制，重算排队与建议；提示受影响的架次清单 |
| 6 | 全程 | 每次状态变更写审计；同一状态重复上报按幂等处理 |

#### 1.3.7 F-06 排队与自动分配

| 步 | 系统行为 | 参数/约束 |
| --- | --- | --- |
| 1 | 入队 | 队列键 `(siteId, usage)`；记录优先级、入队时间、期望窗口 |
| 2 | 排序 | `priority` 数值升序（P0 最前）→ `enqueuedAt` 升序 → `sortieId` 字典序（保证确定性） |
| 3 | 展示 | 位次、预计等待、前面架次数；每 `refreshMinutes`（建议 1 min）刷新 |
| 4 | 槽释放 | 自动分配给队首，通知确认；`queueConfirmMinutes`（建议 5 min）未确认 → 本次分配作废，顺延下一位，原项保留原位次等待下一次释放（首版默认；降级策略见 DO-08） |
| 5 | 人工调序：仅调度员；跨优先级需双人复核；必须填原因 | 审计含前后位次 |
| 6 | 超时：超 `queueTimeout`（建议 60 min）→ 建议改场/取消；不自动取消 | 运营人确认 |

### 1.4 数据模型设计

#### 1.4.1 分层与实体关系

```
[资源层]  Site 1─n MovementUnit
             1─n Stand
             1─n SiteStatusSnapshot
             1─n ExternalStatusWatermark
                 │
[计划层]  Sortie n─1 Site(起飞) / n─1 Site(落地)
            1─n SlotReservation n─1 MovementUnit
            1─n QueueItem
            1─n Directive
                 │
[执行层]  SlotReservation 1─n Occupation
            1─n StandAssignment n─1 Stand
            1─n ConflictRecord 1─n RuleHit
                 │
[治理层]  ParameterVersion 1─n RuleHit
            AuditLog（只追加）
            OutboxEvent（事务内写，异步投递）
            Notification
```

**建模红线（继承上游 1.7.3 三条，设计再加一条）**

1. 起降单元 ≠ 停机位：单元按秒级动作占用，机位按分钟级周转占用；两者不能共用一张「资源占用表」的语义。
2. 预约态 ≠ 占用态：预约是计划权利，占用是物理事实；报表必须分口径。
3. 审批态 ≠ 调度态：`flightPlanRef` 只做计划关联，`flightPlanState` 只读同步审批态（9 态，E-11），`dispatchState` 独立演进；审批通过是「放行」前置，不是「锁槽」前置（默认口径，见 DO-13）。
4. **（设计补充）容量 ≠ 资源占用**：容量是「小时窗口内的起降动作计数」，不是「同时占用数」；不能用当前占用数反推容量。

#### 1.4.2 实体清单

| 实体 | 作用 | 主键/业务键 | 生命周期 |
| --- | --- | --- | --- |
| Site | 起降场台账 | siteId；业务键 siteCode | 长期，状态可变 |
| SiteStatusSnapshot | 场地状态变更快照（只追加） | snapshotId；`(siteId, effectiveAt)` | 永久留存（可归档） |
| CapacityAssessment | 容量评估记录（评估方/依据/日期/有效期） | assessmentId；`(siteId, assessedAt)` | 只追加；新记录生效后旧记录保留 |
| MovementUnit | 起降单元（跑道/起降坪/FATO） | unitId；`(siteId, unitCode)` | 长期 |
| Stand | 停机位 | standId；`(siteId, standCode)` | 长期 |
| Sortie | 架次，调度最小对象 | sortieId；业务键 sortieNo | 草稿可删；提交后只可取消，不物理删 |
| SlotReservation | 槽预约（锁定/已确认/使用中/已释放/已过期/已作废） | reservationId；`(sortieId, siteId, usage, seq)` | 每个架次至少两条（起飞/落地）；跨场分属两场 |
| Occupation | 实际占用区间（单元/机位） | occupationId；`(resourceType, resourceId, startAt)` | 只追加，释放写 endAt/reason |
| StandAssignment | 落地后的机位分配与周转 | assignmentId；`(sortieId, standId)` | 随架次结束 |
| QueueItem | 排队项 | queueId；`(siteId, usage, sortieId)` 唯一 | 等待/已分配/已放弃/已超时 |
| Directive | 调配建议（改槽/等待/改场/备降/让行） | directiveId；`(sortieId, type, createdAt)` | 待确认/已接受/已拒绝/已过期 |
| ConflictRecord | 一次冲突判定结果 | conflictId；`(resourceType, resourceId, windowStart, counterpartId)` | 只追加；可标记已处置 |
| RuleHit | 规则命中明细（可解释） | hitId；`(conflictId/operationId, ruleId)` | 随操作/冲突留存 |
| ParameterVersion | 参数版本 | parameterVersionId；`(scope, versionNo)` | 不可变；新版本追加 |
| AuditLog | 操作审计 | logId；`(occurredAt, actorId)` | 只追加，不可改删 |
| OutboxEvent | 事务内事件 | eventId；`(aggregateType, aggregateId, seq)` | 投递成功后可归档 |
| Notification | 站内/推送通知 | notificationId；`(recipientId, createdAt)` | 保留 90 天（建议） |
| ExternalStatusWatermark | 外部数据新鲜度 | `(source, objectType, objectId)` | 覆盖更新，保留最近 N 次 |

> **等待点（WaitingPoint）不在本系统资源模型内**：它是空域/进近侧概念（术语见上游 requirement.md 1.7.1），P-06 仅展示外部监视/空管数据，不参与排槽、容量与冲突判定；本系统不分配、不排序等待点。

#### 1.4.4 时间、状态与口径（研发必须按此实现）

1. **区间半开**：所有 `[start, end)`；相邻端点不重叠。显示时对用户展示 `start–end`，内部比较一律半开。
2. **三套时间**：计划（plan）、预计（estimated）、实际（actual）分开存；任何报表必须声明用的是哪套。禁止用 `actual` 回填 `plan`。
3. **时区**：统一 UTC+8；存储带偏移的 ISO 8601 或 UTC 时间戳 + 场站时区；界面统一 `YYYY-MM-DD HH:mm:ss (UTC+8)`。外部时钟同步按 E-10。
4. **秒级**：槽按分钟对齐；实际占用、周转、精确计划时刻按秒计算，不允许把秒抹掉后再判定；缓冲口径见 R-05/DO-11。
5. **状态表达**：主状态 17 态只由领域事件迁移（附录 B）；「暂缓放行/等待机位/待重排/复飞中」是 `subStatus`，不参与主状态统计；`blockingReasons` 只解释不驱动状态。`subStatus` 同一时刻只保留一个，按业务阶段互斥（未起飞：暂缓放行/待重排；已落地：等待机位；进近：复飞中）；确需并发的标记放 `flags`，不扩 `subStatus` 枚举。
6. **来源标记**：任何时间、状态、占用必须有 `source ∈ {manual, interface, system}`；报表可按来源拆分，禁止用 `system` 掩盖人工修改。
7. **容量口径**：`assessedCapacity` 单位为「起降动作/小时」；同一架次在起降两场各计 1 次；同场起降计 2 次。若产品负责人选择「架次/小时」，则同场起降计 1 次、跨场各计 0.5 次（不推荐，见 DO-01）。
8. **删除**：业务对象不物理删除；草稿可软删；审计、占用、状态快照、参数版本永久只追加。
9. **槽的排他范围**：槽是固定窗口 `[floor(preciseAt, slotMinutes), +slotMinutes)`；资源按**整槽**排他，精确计划时刻 `preciseAt` 必须落在槽内，但只用于展示与周转；缓冲是否按精确时刻计算取决于 DO-11，**不缩小槽的排他范围**。因此 10:03:27 的申请占用 10:00–10:05，而不是 10:03:27–10:08:27。
10. **审批闸门**：`approvalGateMode` 默认 `release`：锁槽/确认不校验审批态；进入「待起飞」前必须 `flightPlanState=审批通过`，或 `approvalExemptionRef` 非空（书面豁免 + 双人复核 + 审计）。配置为 `slot` 时，R-01 前（R-17 之后）增加审批态校验；配置为 `none` 仅用于演示/沙盒，不得用于生产。

#### 1.4.5 一致性、并发与审计

| 机制 | 设计 | 防的是什么 |
| --- | --- | --- |
| 资源锁行 | 每个 `(resourceType, resourceId)` 一行锁记录；写预约/占用时先取该行锁，再精确复核区间 | 多实例并发下「两人同时抢同一槽」 |
| 精确区间复核 | 在锁内查询同一资源的预约槽窗口与实际占用是否重叠（末端加 buffer） | 唯一键无法表达带 buffer 的重叠 |
| 乐观锁 | `Sortie.version` / `SlotReservation.version`；请求带版本，落后返回 `STALE_VERSION` | 覆盖他人修改 |
| 幂等键 | 写请求带 `Idempotency-Key`；同键同 payload 返回首次结果；同键不同 payload 返回 `IDEMPOTENT_CONFLICT` | 重试/双击/网络抖动导致重复预约 |
| 审计 outbox | 业务写与 `AuditLog`/`OutboxEvent` 同事务；异步投递失败可重试；审计查询读库 | 「业务成功、审计丢了」 |
| 状态迁移守卫 | 只允许附录 B 的迁移；非法迁移返回 `INVALID_TRANSITION`；迁移时清理不再适用的 `subStatus`/`blockingReasons` | 前端绕过/脚本直改状态；旧子状态污染新主状态 |
| 读模型 | P-01/P-04 的聚合读模型可异步刷新；写操作永远读主库 | 读模型延迟导致误判 |

> **反例（不要这样做）**：用「每分钟一行」的唯一键表当最终判定。秒级边界会产生误判（例如既有区间 10:00:30–10:01:30、缓冲 60s，新预约 10:02:30 恰好满足「不小于」但会撞桶）。时间桶只能做读模型/预筛，最终判定必须在资源锁内做精确区间比较。

### 1.5 规则设计

#### 1.5.1 规则执行管线

任何写操作按固定顺序执行，**先快照、后判定、再落库**：

| 阶段 | 内容 | 失败处理 |
| --- | --- | --- |
| P0 参数快照 | 读取当前生效 `ParameterVersion`，固定到本次操作 | 无生效版本 → `CONFIG_MISSING`，拒绝写操作 |
| P1 身份与数据范围 | 认证、角色、数据范围、双人复核令牌 | `FORBIDDEN` / `REVIEW_REQUIRED` |
| P2 静态准入 | **R-17 状态新鲜度 →（`approvalGateMode=slot` 时审批态）→ R-01 场地/时段 → R-02 机型/设施**（先判新鲜度，避免用过期状态做准入） | 返回具体原因码，不生成预约；STALE 优先于 SITE_CLOSED |
| P3 资源与容量 | R-03 粒度、R-04 互斥、R-05 缓冲、R-06 周转、R-07 容量、R-16 双段槽 | 返回冲突对象与建议 |
| P4 流程与状态 | R-08 排队、R-09 让行、R-10 延误、R-11 放行、R-12 落地、R-13 场地联动 | 返回阻塞项/建议，不静默改状态 |
| P5 并发与幂等 | R-15 版本/幂等 | `STALE_VERSION` / 幂等重放 |
| P6 落库与留痕 | 写业务表 + 审计 + outbox + 通知 | 同事务回滚；通知失败不回滚业务 |

**判定结果结构**：一次操作可命中多条规则，返回 `RuleHit[]`；`blocking=true` 的第一条决定拒绝码，其余作为解释与建议保留。UI 不得只显示「操作失败」，必须显示「哪条规则、哪个对象、哪个时间窗、哪个参数值」。

#### 1.5.2 规则判定表（R-01～R-17）

> 写法统一为「当…时，应…；否则…」。R-01～R-15 继承上游；R-16/R-17 为本设计补充，标注「设计补充，待确认」。其中 R-01 增补 `subStatus` 判定、R-04 增补「未释放的实际占用」、R-06 增补「未落地时用预计落地时刻」回退、R-11 增补审批闸门；R-07 的计量单位与 DO-12 口径见对应条目，其余语义不变。

| 规则 | 当…时（判定条件） | 应…（通过/系统行为） | 否则…（拒绝/兜底） | 错误码 | 参数 | 依据/状态 |
| --- | --- | --- | --- | --- | --- | --- |
| R-01 场地可用性 | 提交时 `Site.status ∈ {未启用,停航,故障,管制}`，或 `subStatus ∈ {维护中,临时关闭,应急占用}`，或计划时刻不在 `openWindows` 内 | 继续 R-02 | 拒绝并返回具体原因；给出最近可用时段 | `SITE_CLOSED` / `SITE_FAULT` / `SITE_RESTRICTED` / `OUT_OF_WINDOW` | 无 | E-14、E-17 |
| R-02 机型适配 | 机型等级 > 场级或单元级 `maxAircraftClass`，或重量 > `maxTakeoffWeight`，或起降方式与 `supportMode` 不符 | 继续 R-03 | 拒绝，指出超限字段 | `AIRCRAFT_NOT_SUPPORTED` | 机型字典 | E-14、E-17 |
| R-03 槽粒度对齐 | 生成/接受预约时刻 | `slotStart` 向下对齐粒度，`slotEnd=slotStart+粒度`；返回精确时刻与槽 | 缺时区/缺秒精度 → 拒绝 | `INVALID_TIME` | `slotMinutes=5`（建议） | E-10；槽粒度无标准（U-01） |
| R-04 槽占用互斥 | 同一 `(siteId, unitId)` 存在「锁定/已确认/使用中」预约，**或存在未释放的实际占用 `Occupation`**，且与新槽窗口重叠（首版不区分 usage） | 创建「锁定」预约，TTL 到期释放 | 拒绝，返回冲突预约号/占用号/操作人 | `SLOT_CONFLICT` | `lockTtlMinutes=10`（建议） | 92 部第 92.531 条（E-05）；并行性 U-04 |
| R-05 缓冲间隔 | `newSlotStart < existingEnd + B` 且 `newSlotEnd + B > existingStart`（预约取对齐后的槽边界；实际占用取秒级实际起止；existing 含锁定/已确认/使用中的预约与未释放的实际占用） | 判定通过 | 判定间隔不足，拒绝/告警 | `BUFFER_VIOLATION` | `bufferSeconds=60`（建议，场/单元可覆盖） | E-05；具体秒数无标准（U-02） |
| R-06 周转间隔 | 同一机位：`(actualLandingAt 或 estimatedLandingAt) + turnaround + charging > 后架次 planTakeoffAt` | 允许分配并按区间占用 | 拒绝该机位，推荐次优机位 | `TURNAROUND_VIOLATION` | 多旋翼 6 min、换电 +4 min、eVTOL 15 min（演示值） | 无标准（U-03） |
| R-07 容量上限 | 某 `(siteId, 自然小时)` 内「锁定+已确认+使用中」的**起降动作**数 ≥ `assessedCapacity`（建议口径；上游仅「已确认+使用中」，见 DO-12） | 置「容量饱和」，拒绝新增并给最近可用窗口；≥90% 仅告警 | 正常受理 | `CAPACITY_EXCEEDED` | `assessedCapacity` 来自评估记录；`warnRatio=0.9` | E-01、E-30；计量单位 DO-01、窗口口径 DO-02 |
| R-08 排队排序 | 无可用槽且运营人选择排队 | 建排队项；按 `(priority 升序, enqueuedAt 升序, sortieId)` 定位次；槽释放自动分配并通知；被通知方 `queueConfirmMinutes` 内未确认 → 本次分配作废，顺延下一位，原项保留原位次等待下一次释放（首版默认） | 保持位次，每 1 min 刷新预计等待；记录 `queueMissCount`，降级策略见 DO-08 | `QUEUE_FULL`（可配上限） | `queueConfirmMinutes=5`、`refreshMinutes=1` | 设计补充；排序规则待确认（U-05） |

| R-12 落地与机位 | 收到落地报告（人工/监视补录） | 按单元类型释放：垂直起降单元接地即释放，跑道型在 `actualLandingAt + runwayExitSeconds` 释放；同时按机型/充电/就近/周转分配机位并计时 | 无机位 → `subStatus=等待机位` + 容量告警；不得默认占位；每 1 min 重试 | `NO_STAND_AVAILABLE` | `standRetryMinutes=1` | E-15、E-16；状态缺口 DD-05 |

| R-14 人工干预审计 | 任何人对预约/占用/优先级/状态写操作 | 记录 actor/角色/时间/对象/前后值/原因/IP；原因必填且非空 | 原因空白/「无」→ 拒绝操作 | `AUDIT_REQUIRED` | 无 | E-09、E-08 |
| R-15 幂等与并发 | 同一 `sortieId + version` 重复请求；或版本落后 | 同键同 payload 返回首次结果；版本落后返回 `STALE_VERSION` 并提示刷新 | 正常处理并 `version+1` | `STALE_VERSION` / `IDEMPOTENT_CONFLICT` | 幂等键 24h | E-26 |
| **R-16 双段槽原子性**（设计补充） | 架次需要起飞槽 + 落地槽（同场或跨场） | 同一次请求内锁定两段槽；跨场时两场都成功，同场时两段都成功，才确认；任一失败释放另一段并返回失败场/段 | 拒绝整单，不得只保留单段预约 | `DUAL_SLOT_FAILED` | 与 R-04/R-05 同参 | 演示数据有 10 个跨场架次；上游无对应规则，**待确认** |
| **R-17 状态新鲜度**（设计补充） | 外部场地状态最后更新时间超过 `staleThresholdMinutes` | 标记 `STALE`，P-01 灰显「状态失联」，该场新增预约拒绝 | 未超阈值 → 保持 `FRESH`；超阈值且需临时放行 → 调度员可在 `staleOverrideMinutes` 内强制覆盖：原因 + 双人复核 + 审计，到期回 `STALE` | `EXTERNAL_STALE` | `staleThresholdMinutes=5`、`staleOverrideMinutes=30`（建议） | E-16、E-26；阈值无标准（U-13） |

> **释放三件套（研发不要只做一半）**：任何释放动作必须同时完成：①预约置「已释放/已过期/已作废」；②若存在实际占用，写 `endAt`/`releaseReason`；③资源状态回「可用」（仅当无其他有效预约/占用）。三者缺一即视为数据不一致，需巡检告警并写审计。

> **槽与缓冲的叠加效应（必须评审）**：按 R-05 当前公式，5 min 槽 + 60s 缓冲会让相邻槽（10:00–10:05 与 10:05–10:10）被判冲突，实际最小 headway 变成 10 min；2 个单元的理论可排量约 12 起降动作/h，可能低于评估容量 24 起降动作/h。这不是实现 bug，而是「槽窗口」与「缓冲」两个口径叠加的量化效应。若产品要求 5 min 连续起降，应改为「按精确起降时刻的最小 headway」（DO-11），不得由研发私自改公式；P-04 必须同时显示「评估容量」与「按当前参数可排容量」，不得混用。

#### 1.5.3 冲突判定与可解释输出

**判定对象**

| 冲突类型 | 资源键 | 计数状态 | 说明 |
| --- | --- | --- | --- |
| 槽重叠 | `(siteId, unitId)` | 锁定/已确认/使用中 + 未释放的实际占用 | 首版不区分起降用途；同槽一起一降一律冲突（U-04 选 A） |
| 缓冲不足 | `(siteId, unitId)` | 同上 | 槽窗口末端加 buffer，不扩展起点 |
| 周转不足 | `(siteId, standId)` | 已分配/占用 | 机位占用区间 = `[landingAt, standFreeAt)` |
| 容量超限 | `(siteId, 自然小时)` | 锁定/已确认/使用中（DO-12） | 计量单位为起降动作（DO-01） |

**判定步骤（研发按此实现，不写代码）**

1. 归一化：所有区间转半开 `[start, end)`；`end = end + buffer`（仅单元类）；机位类 `end = landingAt + turnaround + charging`。未释放的实际占用，`end` 暂取 `now`，缓冲比较按 `now + B`；新槽起点早于 `now + B` 即冲突，不因「还没报落地」而放行。
2. 过滤：排除自身 `reservationId`；排除 `已释放/已过期/已作废`；按资源键分组。
3. 排序：组内按 `start` 升序、`end` 升序。
4. 扫描：维护「活动区间」集合，淘汰 `end <= newStart` 的区间；剩余区间若 `newStart < existingEnd` 且 `newEnd > existingStart`，即冲突。
5. 归因：为每条冲突生成 `ConflictRecord` + `RuleHit`，字段见 1.5.6。
6. 建议：生成 2–3 个候选（改槽到最近空档、改场、排队），带「预计等待/影响架次/是否跨优先级」对比；**建议不自动执行**（E-22 的「2–3 个备选方案及优劣对比」）。
7. 严重度：高=实际重叠；中=缓冲/周转不足；低=容量 ≥90% 预警。**该分级是本设计定义，标准/资料只出现「高/中/低」字样，未给判定阈值**（E-22），需产品确认。

**为什么不在数据库用唯一键解决**：唯一键只能表达「同一精确键不可重复」，表达不了「带 60s 缓冲的区间不重叠」，也表达不了「跨场两预约原子性」。因此采用「资源锁 + 精确复核 + 幂等键」，唯一键只用于业务单号/队列项等天然唯一对象。

#### 1.5.4 排队、优先级与顺延

| 项 | 设计 | 状态 |
| --- | --- | --- |
| 优先级 | P0 应急/救援 > P1 医疗/警务/公共安全 > P2 载人 > P3 物流/作业 > P4 训练/测试 | 建议值（U-05），未拍板 |
| 排序键 | `priority` 数值升序 → `enqueuedAt` 升序 → `sortieId` 字典序 | 确定性排序，避免「同优先级看心情」 |
| 同级插队 | 默认禁止；调度员可人工调序，需原因；跨优先级需双人复核 | 设计约束 |
| 抢占 | **禁止自动抢占**；只生成让行建议，需被让行方确认或双人复核 | R-09 / DD-09 |
| 老化 | 首版不做 aging（避免「等久了自动升级」造成优先级失真） | 待确认（DO-08） |
| 顺延 | 槽释放自动通知队首；5 min 未确认 → 本次分配作废、下一位；原项保留原位次等待下一次释放（首版默认，降级见 DO-08） | R-08 |
| 队列上限 | 每 `(siteId, usage)` 可配上限（CFG-21）；超过返回 `QUEUE_FULL` 并建议改场 | 待确认（DO-08） |
| 应急预留 | 是否给 P0/P1 预留容量/机位，见 DO-09；首版不默认开启 | 待确认 |

> **强制让行的边界**：双人复核只是内部管控，不等于被让行方同意。若预约已形成合同或收费上的权利，强制让行须有场地运营规则或合同依据；UI 必须打「强制让行」标记，并记录标准理由模板。**建议首版默认关闭该能力**，只保留「等待对方确认」；是否开启由业主/法务确认（并入 DO-09）。

| 拖拽改槽 | 拖动显示目标槽与影响面浮层；松手弹「影响预览」：受影响后续架次、机位占用、跨场联动、需通知对象；确认+原因后提交 |
| 非拖拽替代 | 每块提供「改槽」按钮与键盘操作，避免只能拖拽（可访问性） |
| 空态 | 无单元：「该场未配置起降单元，先去 P-02」；无预约：「今日暂无预约，去 P-03 创建」 |
| 异常态 | 数据延迟 >30s：右上角「数据截至 HH:mm:ss」；接口失败：保留上次快照 + 灰条；容量记录缺失：容量条显示「未评估」并禁止新增 |

**冲突标记必须可解释**：点击红块，浮层第一行给「与 XX 架次在 U1 10:05–10:10 重叠；缓冲要求 60s，实际 0s」，第二行给「改到 10:10 或换 U2」两个候选。

#### 1.6.7 视觉、文案与可访问性约束

1. **时间**：统一 `YYYY-MM-DD HH:mm:ss (UTC+8)`；悬停显示「3 分钟前」；跨日必须显示日期，不允许只显示 `10:05`。
2. **颜色**：状态不能只靠颜色。开航=绿+「开航」；停航/故障/管制=红/橙+图标+文字；未启用/失联=灰+「未启用/失联」；延误=橙；完成=灰。对比度 ≥4.5:1。
3. **来源徽标**：所有时间/状态旁显示 `系统 / 人工 / 接口` 小徽标；报表可按来源拆分。
4. **免责声明**：P-01/P-05/P-06 底部固定「本系统提供的建议与状态不构成管制指令；飞行放行以空管机构/其委托服务方确认为准」。
5. **可访问性**：所有拖拽操作有按钮替代；键盘可完成「选中块→改槽→确认」；焦点可见；错误提示与字段关联。
6. **密度**：以 1440×900 为基线，最低 1280×720；P-04 首列冻结、横向滚动；移动端单手可触达主按钮。
7. **文案**：拒绝提示必须「原因 + 下一步」，例如「U1 10:00–10:05 已被 SF-0231 占用（已确认）。可改到 10:10，或换 U2。」禁止「系统错误」「操作失败」。

| X-05 | 通知渠道 | 站内、短信、推送 | 出站 | 本地 | 失败重试 3 次；仍失败 → 站内补发 + 待办；不回滚业务 |
| X-06 | 监管上报/导出 | 报表、事件、审计 | 出站 | 本地生成 | 失败 → 异步任务 + 重试；不阻塞调度 |

**权威性与冲突解决**

1. 场地**运行状态**以外部运营系统为准；本系统手工覆盖只作为临时兜底，必须带 `expireAt`，到期自动回到外部状态。
2. 飞行计划**审批态**以空管/UOM 为准；本系统不得本地改成「审批通过」。
3. **预约/占用**以本系统为准；外部系统的机位占用作为对账输入，不一致时生成差异工单，不静默覆盖。
4. **实际起降时刻**：人工报告优先进入业务记录；监视数据用于补录与偏差校验；两者差异 > `timeDeviationTolerance`（建议 60s）时标记「待复核」，不自动改写。
5. 所有外部数据带 `sourceTimestamp` 与 `receivedAt`；新鲜度按 `receivedAt` 计算，避免上游时间造假。

### 1.10 研发红线（评审不通过项）

### 3.4 评审会上必须回答的 8 个问题

1. 首版到底服务「一个起降场运营方」还是「一个片区的多个场」？（影响数据范围、跨场规则、部署）
2. 四项默认参数（槽粒度、缓冲、周转、优先级）由谁签字？签字前研发是否只做可配置空壳？
3. 系统是否接触「飞行活动申请/起飞前确认」的审批结果？若接触，是只读同步还是代为提交？审批通过是「排槽」前置还是「放行」前置？（影响 U-08/U-09/DO-13）
4. 状态失联时，运营方能接受「阻断新增预约」吗？还是宁可告警也要接单？（DO-06）
5. 跨场架次是否允许「先飞后补落地槽」？（DO-05；运营现实可能要求，但设计默认不允许）
6. 应急任务是否预留容量？若预留，预留比例、启用权限、释放规则是什么？（DO-09）
7. 5 min 槽是否允许相邻槽连续起降？若允许，buffer 必须改为「精确时刻最小 headway」，还是接受 10 min 的实际 headway？（DO-11；直接决定容量与 P-04 读数）
8. 锁定中的预约是否占用小时容量？若占用，10 min TTL 会造成临时饱和；若不占用，确认时可能被拒。（DO-12；直接决定 AC-09 与 P-04 读数）

## 附录 D：术语补充（只列本设计新增/易混）

| 术语 | 本设计口径 |
| --- | --- |
| 起降动作（movement） | 一次起飞或一次落地；容量计量建议单位（DO-01） |
| 锁定（hold） | 排槽成功后、确认前的临时占位，带 TTL；不是「已确认」 |
| 已确认（confirmed） | 运营人/调度员确认后的预约权利；仍不是「实际占用」 |
| 占用（occupation） | 实际时间轴上的物理占用，精确到秒；由报起飞/落地/分配机位产生 |
| 缓冲（buffer） | 同一单元两次起降之间要求的最小空档；只扩区间末端 |
| 周转（turnaround） | 落地后到机位可再起飞的时间；含充换电附加 |
| 暂缓放行 | `subStatus`：起飞前校验未过，主状态仍「已确认」 |
| 等待机位 | `subStatus`：已落地但无机位，主状态仍「已落地」 |
| 待重排 | `subStatus`：场地突变后已确认预约需要改槽，主状态不变 |
| 复飞中 | `subStatus`：进近复飞，主状态仍「进近」；计 `goAroundCount` |
| 让行建议 | Directive 的一种；需被让行方确认/双人复核，不自动改槽 |
